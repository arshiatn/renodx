**Scoring a row's look** (`tools/tw/quality`, report.md there; `g2b/g2b_quality.sh` runs it in its own folder with the smoke feature): the harness's 640x360 box scene traced per feature (`sun`, `ao`, `bounce`, `torch`, `smoke`), each scored against its reference, the feature's raw estimator with no history averaged to 0.5% standard error (paths 16 a texel, smoke 64 particles a ray). A setting is one line of `settings.txt` (the row's bridge flag through `RT_EXTRA_TRACE_FLAGS` or `HARNESS_QUALITY_PATH_FLAGS`, a helper switch such as `RENODX_TW_SMOKE_FAST_BUILD`, `HARNESS_QUALITY_RR=0` for the picture through Ray Reconstruction, `RENODX_TW_NO_TRACE_HISTORY=1` for the AO and torches without their history, `HARNESS_QUALITY_RAW=1` for every history off); `pair <helper> <out> <off> <on>` scores the row off and on against the same reference, still and moving. Read rRMSE with its parts: bias (darkening, blur, a pattern that stays), noise (boiling), swim / noise (blotches), the 1-frame correlation (lag). A difference inside two references' own disagreement (~0.35%) or one run's spread is "no look change": the row is decided by its cost. Ray effects are judged this way against the many-sample reference without the denoiser; an "as vanilla" row (ours in place of a game pass) is judged against the game's own output by a WARP test on its bytes ("0 values differ"), which the scorer can't make; taste rows (Hue Clip, look sliders) stay the maintainer's. Ray Reconstruction scores depend on the DLL (`RR=310.9` takes the maintainer's 310.9.16 for a call; the shared harness folder keeps 310.7): compare RR rows within one DLL. The scorer has no fog, reflections, water, upscaling or game passes.

Rules:

- Compare `all_modes.sh` runs by mode name against the last log, not by count. Run it in the background beside compiling, not beside another GPU job, and don't copy a helper into its folder until it ends.
- `game-port-method`'s run-counts rule; a second game once failed silently.
- Rows that depend on each other: every combination a player can set gets a case (page-dump state, harness mode or scorer line), not only the defaults and presets ([shaders-ui.md](shaders-ui.md) section 3).
- Every replaced shader gets a vanilla-exact test against the game's bytes ([hdr-review-rules.md](../../game-port-method/references/hdr-review-rules.md)'s Vanilla exact first). Give WARP tests the game's real ranges, and a control that must fail.
- Scale a WARP formula check's tolerance with the largest summed term, not a fixed epsilon [f306ff2d].
- A test written for a known bias runs both ways: before the fix `-Expect now` passes (today's values hold and the exact ones fail: the bias is seen), after it `-Expect exact` passes and `now` fails (`test/tw_rt_open_sky`) [a91dbe84]. A prediction table from the closed form, every cell within 4 standard errors, beats a single tolerance.
- A NaN, Inf or negative census reads float outputs only: a NaN stored to an UNORM target becomes 0, and maps that hold bit-cast words (the light mask's ratio words) read as NaN by design. A run's last-frame dumps say nothing about other frames: a per-frame census belongs in the run.
- A texture read checked against a game PS's pixel: bilinear weights have 8 bits an axis and the PS's inputs come interpolated (a constant 1-2 ulps off), so a smooth texture may differ by 2/256 of its largest texel step times the decode's slope. For a 4-ulp check give the texture plateaus where it is read [df95f06e].
- WARP's bilinear weights at one texel coordinate differ with the texture's size: a picture-in-a-bigger-texture scale test at a share that isn't a power of two (33%) with reads off the texel centres (a distortion) misses by a weight step even with the coordinates 7.6e-6 texels apart (Pharaoh's SSR apply: 2,112 values). Check such a read with a point sampler and its coordinates with a probe (`warp_tests/pharaoh/apply_share_v62`) [7224b347].
- The frame trace logs every draw and dispatch in its own callback, also the ones another callback bypasses: a skipped chain still shows. Prove a skip by the add-on's skip-path line. Its options `blend_hashes`, `vertex_input_hashes`, `instances_apart` (`twattila/frame_trace.hpp`, 7e945569) give a PS's blend desc, a VS's buffer slots with strides and element counts, and index x instance counts apart in one run.
- Pack searches: `mmap.find` on literal names takes minutes over 75 GB; a regex with a `{0,120}` prefix ran 30 minutes with no output.
- The helper's status line's GPU ms are one request's (the last answered), not a mean, and the "Ray tracing with" line comes 3 s after a settings change: read high values against the settings changes around them (a 19-40 ms bounce "spike" was a held Rays setting between two changes). Means and parts come from Record Ray Tracing Profile (`tw_rt_profile_helper.csv`).
- Say in the report what the harness can't show.

## 2. Game runs

- Permission and backups: `game-port-method`'s Game runs rule. It covers the scripts that start a game too (`run_game`, `soak`, `fg_run`, `fg_mem_test`, `shot_run3`, `install`, `overlay_test`, `profile_run2`).
- Run on the maintainer's current ini and preset (the proof levels in `game-port-method`); a "0 of 8" once held only for one ini.
- Never two GPU jobs at once. Before each start, Committed Bytes below about 60 GB (dead processes from resets hold theirs until a reboot, [helper-fg-stability.md](helper-fg-stability.md)).
- The game folder holds plain stamped copies before a run: Pharaoh's addon and a DevKit were symlinks into `build/Release` (as of 2026-11), so any build would have swapped the addon mid-run and the DevKit broke the no-DevKit rule. `ls -l` the folder first.
- **Driving a run**: `test_scripts/run_game.ps1` (`-Game`, `-Shot s`, `-Profile s`, `-Set "s:key=value;..."`, `-Env`, `-Keys "W:6.4"`, `-Campaign`) sets `RENODX_TW_SHOT`, `RENODX_TW_PROFILE`, `RENODX_TW_SET` (`twattila/test_hooks.hpp`) and closes the game through its window; `wh3_batch3/check_run.py` proves the run ran.
- Steam started elevated (the maintainer's SteamAdminStart task) passes that to the game and blocks input: `(Get-Process steam).Path` empty means elevated; `steam.exe -shutdown`, then `-silent`; don't touch the task.
- Start forms: `game_startup_mode replay "<full path>"` (WH3 crashes on a bare name), `campaign_load "<save>"`, `battle_benchmark "<xml>"` (WH3). Try them before building a plan on one.
- A guessed start argument can crash the game before any frame: Pharaoh's `game_startup_mode campaign <benchmark>` did (0xC0000005); its help lists `battle|campaign|... <xml>` and no replay or campaign_load. One try per guessed form, and say it was a guess. A plain `game_startup_mode campaign` crashed the same way (both a null read at Pharaoh.exe+0x47C81A, read from the crash_report minidump's exception stream): Pharaoh's campaign is reached only from the menu (Load), so campaign traces need the maintainer's load and the `renodx_trace_now` marker.
- Rome II crashes before any frame from the command line, also without the add-on: `game_startup_mode battle <xml>` at Empire.Retail.dll+0x276899, `campaign_load <save>` at +0x103661. Its traces, like Pharaoh's campaign's, come from the maintainer's own menu starts while `rome2/atn_trace_watch.ps1` (`-Game`, `-Process`, `-Runs` for other games) drops the marker every few seconds and moves each trace into a run folder.
- A desktop capture (`CopyFromScreen`) of an HDR flip-model game window returned one stale frame (Pharaoh's loading screen, three shots alike): take pictures with ReShade's screenshot or `RENODX_TW_SHOT`. ReShade's screenshot key is each ini's `KeyScreenshot`, a virtual-key code (44 Print Screen; Rome II and WH2 112, F1; Attila, Pharaoh and WH3 6, a mouse button, as of 2026-11): read it before asking for shots.
- After an unclean exit Rome II's mod manager asks about the mod pack (window class `mod_question_dlg`), and SendInput's Enter doesn't answer it: close every start cleanly (CloseMainWindow, kill only after 60 s); a run script detects the class and stops at once (`rome2_data_run.ps1`).
- Fullscreen Pharaoh draws no frame while another window is in front ("No frame for 20 s"), and the app keeps the foreground: run windowed at full size (`gfx_fullscreen false`, restored from that run's backup).
- `RENODX_TW_SET` is read at launch; its timed changes fire only while frames are drawn and pile up otherwise. Time them from the battle's first-frames line, and place each trace marker after the log shows the value set.
- A key read once at load (`FrameTrace`) must be in `ReShade.ini` before the start: a run script applied its ini option only in its WH3 branch, so an Attila capture asked for a frame trace and got none; check the log's "Frame trace:" line. The ini after a run proves no row's value (the test hooks' setting writes didn't reach it, only ImGui's docking lines changed): read the log's "Test: x set to" lines ([shaders-ui.md](shaders-ui.md) section 3) or a page dump.
- A replay takes no selection input: Ctrl+A sent to Attila in front selected nothing (no indicator draw in the frame trace). Tests that need selected units or ships need the maintainer's play or a live battle.
- In-game MSAA turns the addon's AA off, and the frame trace hangs off the AA frame: an MSAA start gives no trace until the trace has its own path. With it on, DLSS, the rays and FG stay off too (Rome II round 2): an install or a run that needs them sets the game's AA preference off (`gfx_aa 0`) only with the maintainer's OK, from a fresh backup.
- Epic Games Store copies (Troy, WH1, as of 2026-11) can't be started by an agent: Troy.exe started directly shows "Please use the Epic launcher to start the game" and never loads ReShade; warhammer.exe with the `-epicapp` arguments but no exchange code loads the add-on and stays in the frontend (EOS offline). Their traces come from the maintainer's own start with `rome2/atn_trace_watch.ps1`; plan them that way from the start. Old traces of every TW game from 2026-10-27 are in `build/ingame/traces` (an older add-on, the same game passes): use them for presence.
- A game exe with the "Run as administrator" compatibility flag (`RUNASADMIN` under `AppCompatFlags\Layers`, HKCU or HKLM) raises a UAC prompt no agent can answer: Rome Remastered's start failed "canceled by the user" (2026-11-14). Read both keys for the exe while planning a run; only the maintainer may clear the flag or start the game.
- A run script copies every log the game writes (its own log folder, crash reports, mod and message logs) into the run folder before it restores the maintainer's files from that start's backup: Rome Remastered quit 4 s after its start and the restore put the old message_log.txt back, with the game's reason in it (2026-11-14).
- Crashed starts leave `Get-Process` entries with 0 threads until a reboot (six Rome2.exe after the command-line crashes): count only processes with threads, as `tw_install.py` and `atn_trace_watch.ps1` do. Leftover game processes that still run (some unkillable, held by the driver) keep their commit: 15 held about 10 GB (38.8 to 28.5 GB once ended). List them for the maintainer to end as admin after their session; a reboot clears the rest.
- The data run of a new TW game (start, traces, logs, quit) is the one agent run the maintainer allows per new game ([bringup.md](bringup.md) Phase 1); effort, and the hand-over files where the maintainer loads a save, as in `game-port-method`.
- The games read the mouse through DirectInput: synthetic clicks never land. Keys by SendInput scan codes after `SetForegroundWindow`; settings through `ReShade.ini` or `RENODX_TW_SET`.
- Delete `ReShade.log` before waiting on a line (the old log holds it); in WH3 wait for a new "First run: sun light draw", not for the helper.
- Replays end at their own length, then a still results scene: a 20-minute soak held 6 minutes of live battle.
- A plan's list of what test material lacks is a guess until the game's packs are read: WH3's benchmark XMLs held a burning siege.

## 3. The maintainer's test list

The format is `game-port-method`'s. TW additions:

- Each paused run freezes a random wind phase.
- A unit or grass row's cost shows only with the units or the grass on screen: Unit Detail A/Bs in a replay whose camera held few soldiers changed nothing. Name the scene the maintainer measured (their heavy 8x battle), the camera on the units.
- What the build reports itself: "applied" lines, Record Ray Tracing Profile (30 s), Frame Trace, Time Each Pass, a pixel trace; the maintainer sends `ReShade.log`, the helper log and the ini.
- Shots with ReShade's overlay open on the rows under test, their values in the picture: the rows decode a bug faster than a description (three night-city shots told which row pair blew the walls out). FG is off while the overlay is open.
- The page-dump dry-run also checks that the debug view is made (an AO view without the AO row is magenta); a helper once didn't log placed instances the plan relied on.

## 4. Reading the maintainer's evidence

- Copy each set of logs, shots and inis into the round's folder in `tools/tw` before reading, named by run. Then `python -I tools/tw/check_logs.py <folder>` (the data-run scripts and `atn_trace_watch.ps1` print it at their end): known-bad lines in `ReShade.log`, the helper's log and the run's notes (RR unavailable, "no main camera" repeating, a `RENODX_TW_SET` key not applied, a trace not taken, exceptions, removed devices, NOT RUN, a game that ended by itself), exit 1 on any. Pharaoh's run B61 held "Ray Reconstruction unavailable" at 16:28; it was read at 19:55.
- A crash or hang: the game's `crash_report` folder first, then the device-end line, then event 153 ([helper-fg-stability.md](helper-fg-stability.md)). A crash only with the mod: the three control starts (vanilla, ReShade only, the mod) of `game-port-method`'s Measurement section before any theory.
- A profile: segment it by its setting-change log lines before reading numbers; a profile's "states" were once the maintainer stepping through Upscaling Mode.
- A paused pair 30 s apart differed 4 to 5% around the units with nothing changed (banners fade after the pause starts): run the control before blaming a row.
- A brighter picture with rays multiplying is not the rays: one effect at a time, the other shadow method off. RT Shadows on turns Bend off.
- Plant Wind Sway above 1 pulses 13 to 38% of the field dark once a second (Attila only): keep 1 when judging shadows.
- Slow frames report GPU times late: read the last status line (`last_status.py`).
- Name the state a capture ran in from its own logs, not from its label: two sea runs meant as DLAA against Performance both ran at 50% (the maintainer's preset); the helper's "... 1920 x 1080 to 3840 x 2160" upscaling line says the scale.
- A debug view's colours in an HDR10 shot land at PQ codes (Debug View 3's sky near (49, 26, 158)): test which channel dominates, not a value (SDR shots: the Debug View row of [rt-scene.md](rt-scene.md) section 4). Shots compared seconds apart catch moving content: a fireball crossing the sky read as a light rim; look at the crops before a FAIL.

## 5. Profiling

- PresentMon CPU busy and GPU wait before any CPU or GPU work (facts in [helper-fg-stability.md](helper-fg-stability.md) section 5).
- The helper's GPU time from per-process GPU Engine counters.
- Record Ray Tracing Profile for 30 s with ReShade's menu closed (FG is off under the menu); read `answer_wait_ms`, `present_pacing_ms`, `cpu_record_parts`.
- Time Each Pass for one frame; A/B inside one run (`RENODX_TW_SET`).
- Nsight Graphics doesn't attach to 32-bit D3D11 (Attila, Rome II, Thrones): the game's side by Time Each Pass, the helper in the 4K harness with `RENODX_TW_REPLAYABLE` and `RENODX_TW_NO_CLUSTERS` (`tools/tw/nsight`). Its ranked list goes into `HANDOFF.md` line by line (the Nothing dropped rule): the first Attila check's code items were lost at a compaction.
- The game's own CPU hot spots (the CRT's x87 `fmod`, software float to half, x87 truncation blocks, its sort, per-item locks) are fair game: our own detour, bit-exact against the game's function offline (all 2^32 inputs where it takes one float), an Experimental row, never on bytes a third-party fix patches (read the live bytes first). A third-party fix's own code stays its author's: a patch goes to the author, with the maintainer's OK.
- A CPU question needs a sampled profile, a GPU question one with GPU events: `wpr -start CPU -filemode` (GPU: `-start GPU -start CPU`), then `wpr -stop <file>.etl`, through the maintainer's tasks (`game-port-method`); read it with xperf or WPA (`Windows Kits\10\Windows Performance Toolkit`) by module offsets. PresentMon alone guesses.
- The WPR start task takes a fullscreen game out of front: the first captures held no 3D draw (game GPU busy 0.3 ms, rays released after 10 s). Bring the game back with input events 2 and 4 s after the start and again after the stop, schedule the RT profile and Time Each Pass inside the window, and count a capture only with 200 or more independent-flip presents inside it (PresentMon). WPR costs 4-6% of frame time: never in a measured start; mechanism starts are their own label.
- A draw's time in Time Each Pass includes the game's GPU waiting for the helper at that draw: the sun draw C64DB947 with Light Bounce on minus off was +3.3 ms at 4K, of which 3.16 ms were the helper's paths (RT profile `gpu_paths_ms`) and the apply 0.1-0.3 ms. Subtract the helper's own profile before naming a pass's cost.
- Lock time in a profile can be call count, not contention: Attila's render thread never waited for another add-on thread; the SRW time was the lock and unlock calls themselves, so fewer lock calls is the whole gain.
- Name a hot spot from its disassembly, not a script's bucket label (0x1a280f0, labelled "memset", is the CRT memcpy's block path). The installed add-on's PDB names none of its LTO code: build the same sources with /Z7 to name it; a frame-pointer build (/Oy-) only for mechanism starts, never as an A/B baseline. Worker code without frame pointers gives stacks one frame deep: its callers need a sampler that suspends a thread and reads the return address. Hot lines on the first read of game data (OnDrawScrub on the game's cell record) are the cache miss the game's own code pays next: no memo in front cuts it.
- The critical-path rule (`game-port-method`), TW's case: heapfix's sort, 6-7x faster, changed nothing in a GPU-bound replay (54.45 against 54.35 fps) and was 3.6% slower with 4 threads in a CPU-bound one, where the render thread never waited on it. Find the waiting thread in a profile before building the A/B.

## 6. Other traps

| Trap | How to avoid |
|---|---|
| Reports without a check | Numbers from the run, else "not checked" |
| A fix proves half | Keep the repro after the first fix |
| Debug layer | Needs Graphics Tools; deterministic for lifetime bugs (`RENODX_TW_D3D12_DEBUG`) |
| A lambda with `CHECK` must return int | Exit 3 with no output otherwise |
| Script corruption; a German decimal comma in `-f` | InvariantCulture; read before running |
| PowerShell variable names ignore case: `$start` overwrote a `[string]$Start` parameter (rome2_data_run.ps1, then again romeremastered_data_run.ps1 with this row in place) | One spelling per name in a script; no local shadowing a parameter. `tools/tw/ps_param_shadow.ps1 <scripts>` lists every assignment to a parameter under another spelling (exit 1); run it on every new run script before its first start |
| An own compute pass in a replaced pass's `on_draw` runs before the mod's push: the settings register holds what the last replaced pass pushed | Bind the settings at the register `shared.h` names; write one value of it out to check it arrives |
| A plan built on one start form or one trace | Two forms or two traces before planning |
| A WARP sun test's comparison sampler on an RGBA32F shadow map returned 0 everywhere | Shadow maps as R32_FLOAT (the game's D32 view), `sun_scale_v61` |
| PowerShell `-Filter "*.addon32.*"` matches plain `.addon32` files too | Never delete by it; old files are renamed aside ([release.md](release.md)) |
| `ps_compare` with random constants hung loop-heavy shaders (Pharaoh t05) and broke fog upsamples; WARP world checks with inputs x1024 read outside 64x64 textures and passed on nothing (WH2) | Constants from a trace (`cbf:`) or range-limited inputs, a control that must fail, `cb_audit` for what the check reads |
| A finder that found 0 looked like "this game has none" (Troy's 167 tweaks) | A suite asserts each game's finder hit count (`test/tw_troy_tweaks`); 0 is a failure |
| A restore deleted every replay outside a name list (the maintainer's WH3 `2.replay`) | `game-port-method`'s backup rule; `wh3_common.ps1` marks the run's start and end; never delete the maintainer's replays or saves |
| The quiet lock (`game-port-method`) | The bench refuses starts while a `tools/tw/testbin` process or a build tool runs |
| PresentMon's `CPUStartDateTime` has no leading zero before 10:00: every summary said "no frames in the window" | `bench_summary.py` pads the hour; the run's data was fine |
| CPU Set Setter's rule not applied yet when a start begins ("first seen never") stopped a whole bench session | `constantinople_bench.ps1` retries that start once (Run-One code 3, the failed folder in `failed\`); a session script doesn't stop between sets |
| heapfix.log is appended across sessions: a first-match check read an older session's line | Read the last match |
| The game rewrites `auto_save.replay` after every battle: a bench on it measured another battle | The bench names its replay and checks its hash before every start; it refuses `auto_save.replay` unless the hash is the known one |
| ReShade names a screenshot by whole seconds: two shots in one second share a name, the second overwrote the first (three lost in one start) | Space a pair's shots 2 s apart; map each file from ReShade's save line in the log (written 25-90 ms before "shot pressed") |
| A centred cursor put a game tooltip ("Shallow water") into every shot | Park the cursor over the sky at the first key; move it every 25-30 s only to keep the game in front |
| A relative exe path in a Python subprocess (run from bash) failed with WinError 2; bash mangles `variants\` paths of a .ps1's arguments | Absolute Windows paths; run .ps1 scripts from PowerShell |
| `wpr -start CPU -start GPU` wrote 16 GB for 47 s (Shogun 2) and its xperf text 70 GB | CPU alone where the question is the CPU; delete dumps after reading them |
| A Grass Dump stalls frames; the game writes grass burn during a battle (256-269 records in 35 s), never the grid | Grass dumps run last in a bench; a GPU grass pass re-reads the burn bytes each update |
| WH3 said "Unable to initialize SteamAPI" twice with Steam not elevated (2026-11-15) | The maintainer restarts Steam; don't retry a third time |
| Expeditions' Unreal main menu took no SendInput keys (Up / Down / Enter / Tab / Space; 2026-11-15): the whole run measured the menu, no save loaded | Bring the window to the front first and screenshot after each key; a menu that stays deaf is a question for the maintainer (a mouse click), not a guess |
| The game process wrote `ReShade.log1`: a short device-probe instance had `ReShade.log` (Expeditions) | Read both logs; a run's "applied" lines may be only in `ReShade.log1` |
| `ngfx-capture` asked "kill the interfering applications (Y/n)" about steam.exe; a script without input took the default and killed Steam (Ryse R0, 2026-11-15). It also won't intercept ReShade's `dxgi.dll` | Never start Nsight's capture tools without `--no-block-on-interfering-application` and an answer of "n" on its input; a ReShade game needs another route (the add-on's own pass timer and frame trace) |
| PresentMon filtered to the game's exe saw nothing with frame generation on: the helper presents (`renodx-tw-dlaa64.exe`) | Unfiltered, or filtered to the helper, while FG is on |
| Ryse's menu remembers its last screen: the scripted keys landed on Campaign > Timeline; `system.cfg` cvars are read before the cvars exist ("Unknown command" in Game.log); `Ryse.exe` started alone exits (Steam DRM) | Esc to the top menu, then a screenshot after each key; cvars through the add-on's console path; start with `steam.exe -applaunch 302510` |
| DLSS Frame Generation ran as FSR FG in 11 of 13 folders: no `sl.interposer.dll` (Streamline 2.14.16) beside the helper (Tales, 2026-11-15) | `tw_install.py` writes `ngx_dlls.STREAMLINE` where missing; the FG status line names DLSS-G ("FG v2") or FSR |
