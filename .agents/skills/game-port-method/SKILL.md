# Game Port Method

How the maintainer's ports are planned and checked, whatever the engine. The Total War rounds learned it; it holds for every game. Engine facts live in the engine's own skill or in [references/engines.md](references/engines.md); this file holds only what is true in every engine. A rule that holds in a second engine moves here, not into two engine skills.

## Before you start

1. `git status`, `git log` and the checklist in `HANDOFF.md`: an earlier attempt may have got further. Continue it, don't redo it.
2. A worktree's base first: `git merge-base --is-ancestor <atn-mods tip> HEAD`. Worktrees have been cut from `main`; reset only your own worktree.
3. Read the target game's own shader, buffer and code. Never carry over another game's values, registers, slots, formulas or offsets unread: "same as game X" needs file and symbol for both games.
4. Ask of every feature: does the game already do this? The same effect computed twice is the most common waste.
5. Order the work by what it needs, each piece's offline check green before the next.

## Proof levels for a game fact

Everything a port assumes about a game is one of these. Note the level in the commit.

| Level | What was seen | What may ship |
|---|---|---|
| A | Pass seen in a frame trace or capture, and its bytes read | Ships normally; still off by default if it changes the picture when wrong |
| B | In the shader dump with bytes read, not in any trace | Off by default, Experimental, a line on the in-game test list |
| C | Needs a value or hash nobody has seen | Left out, row hidden, a line on the test list |

Where the engine has no offline shader dump (a packed cache, code a protection hides), level B means "seen in a runtime dump" ([references/engines.md](references/engines.md)). A hash goes in only with its proof in the commit message: the shader's name or family, the bytes read, the trace line if any. A value read from an agent's game run counts as level A only if the run used the maintainer's ini and preset: agent settings once hid a game's GI from a whole round. WARP is for exact-byte and identity proofs; renders that only need numbers run on the GPU (the harness, with a gate id): long WARP rounds took hours (the maintainer, 2026-11-24).

**Stop a piece when** a hash isn't in the dump, the fix needs a guessed offset or register, two attempts failed at the same offline check, the piece has eaten more than twice its size with no green check, or shared code would change another game's behaviour without a parameter. Then revert only that piece, hide its row, leave a `NOT DONE: what, why, smallest step` line in `HANDOFF.md`, and go on. With a feature unproven, the game must behave exactly as without it.

## The maintainer's rules

- **Game runs** only when the maintainer allows them, per batch; the permission ends when the batch closes. A standing OK covers only what it names (the TW skill lists the ones given). Bundle what needs the game into one run. Back up the maintainer's `ReShade.ini`, `ReShadePreset.ini`, the game's preferences and the replays and saves a run can write right before each install or run, never restore an older copy (a stale restore lost newer preferences, a preset and a replay), compare hashes after. Restores move aside only files the run created inside its own window. The maintainer's standing rules (2026-11-24 / 25): a trace or dump run of any game needs no ask when nothing offline (code, shaders, the harness) can answer or the game's shaders aren't dumped yet; it may load the CPU and GPU (it gathers data, not times), but never starts while he plays (he says so beforehand) or beside a GPU timing job. Every other start only when nothing offline proves the point: a design or review names what only a run shows, a phase's game needs go into one session per game with a purpose line and minutes for each start, starts another start or an offline check already answers are dropped, and an Attila run goes before a big agent wave, not in the middle of it (paused agents lose their cache). GPU harness and gate jobs (the lab, helper tests, pass timing on the GPU) need no ask either, inside a GPU window (CPU work quiet, one GPU job at a time; the maintainer, 2026-11-24); game runs are not among them.
- **Unproven work** ships as an Experimental row, off, with a player tooltip and one verdict line on the test list. Defaults change only from measured numbers. A section's More Options may hold as many Experimental rows as needed; the maintainer decides each row: on by default, in which presets, or left under More Options. Give them the numbers for that decision (cost, what it fixes, what it risks). The maintainer's standing rule (2026-11-15): a row that is faster in the bench and gives the same picture (bit-exact or identical by its test; for a speed row, 2026-11-25: HDR-FLIP says the difference is almost invisible, not exactly zero) goes on by default and loses "(Experimental)"; a row that is faster and scores cleaner (a look change for the better) goes on by default once the maintainer OKs its numbers, named without "Experimental" (Near ReSTIR Reuse: reuse -46%, rRMSE through RR 2.19 to 1.96%); a row that may lower quality goes to the maintainer as a list with its numbers. A proven bug fix (the cause proven, the fix's test passing and its control failing) goes on by default with no Experimental row, also when it changes the look (the maintainer, 2026-11-17; a standing rule, again 2026-11-22: "bug fixes should be always used because they are fixing bugs"); list its look change in numbers (PsychoV35's below-black pixels, Smooth Banner Shadows, the specular occlusion's lobe weights). Offline numbers never kill or hide a look feature (GT-VBAO, GT-VBGI, SSS, a new GI): it ships as an Experimental row, off, row-off byte-identical, for the maintainer's own look (2026-11-24); studies tune it, they are no stop gate. RenoDX writes every row's value to the ini, so a new default reaches only players who never saved the row: check with `git merge-base --is-ancestor <the key's first commit> <the last release>` whether the key shipped.
- **Look**: keep the developers' look; scale quality, distance, resolution and update rates, keep the artists' tuning (blur, colour, roughness); a look change is an Experimental row, off. No temporal dither on coverage: DLSS smears alpha or dissolve that changes every frame (Shogun 2's Grass Fade); use stable per-object thresholds. No flicker fix that dims or compresses highlights (Ryse's Highlight Stability was rejected): fix the source (geometry, motion vectors, jitter, specular aliasing). Recommended uses PsychoV35 in every HDR add-on: a new game takes `twattila/psycho35_settings.hpp` with its own `HUE_CLIP_DEFAULT`, measured, not copied; ask the maintainer for its hue settings.
- **Cost**: no per-frame counters or log lines, no per-frame CPU on the game's thread without a measured reason, hot callbacks return on one atomic; one-frame traces behind a button.
- **Rows**: tooltips short and for players, naming nothing the game lacks, no dev notes; keys stay when rows move or saved values are lost. A row that is right only with another is hidden without it, or every combination a player can set is proven: light from the paths on with their shadows off blew walls out white (`tw-port-checklist`'s shaders-ui.md).
- **Every setting**: players run every shader model, quality level and preset. A pass or permutation the maintainer's settings never draw is still fixed and ported when it can be proven offline (WARP against the game's bytes: level B, Experimental or a test line); skip it only with the one trace it needs or a WON'T GET proof. The one exception: no TAA work outside Attila (next rules).
- **Auto Thickness on** (the maintainer, 2026-11-22): GT-VBAO's and GT-VBGI's Auto Thickness goes on by default in every game and every preset, despite its cost. Each game's default turns on as its group's change merges (until then a row may still default off and read "Experimental").
- **No TAA work outside Attila** (the maintainer, 2026-11-22: "we are putting in DLSS/FSR/XeSS which are so much better"): no fixes or patches to another game's own TAA, and no helper-free TAA ported to it or reworked there; a parity ledger's WON'T GET line names this rule. The upscalers' hooks on a game's TAA pass are upscaler work and stay.
- **Ours replaces the game's, exactly one method per effect** (the maintainer, 2026-11-16): one slider per effect, one method running: AO = the game's / GT-VBAO / ray-traced / path-traced ambient (the paths' blocked rays are the occlusion); GI = the game's / GT-VBGI / ray-traced / path-traced; reflections = the game's SSR / FidelityFX SSSR / ray-traced (they replace the game's SSR and its cube-map specular); sun shadows = the game's maps / the maps + Bend / ray-traced. Bend works with the shadow maps (it adds the contact shadows they miss) and replaces only the game's own contact-shadow march; under ray-traced sun shadows Bend is off. While ours runs, the game's version is skipped or neutral (white AO, no bounce, its contact march off), only the part it replaces (`tw-port-checklist`'s ao-gi.md: split what the pass carries), and it returns exactly when ours is off. Not stacking: shadow maps kept (as cheap as possible) for the readers the rays don't shade (water, fog, particles), and a ray-miss fallback (sky, probe cube) inside the ray-traced method. No double darkening, double bounce or double reflection; the skip also saves its cost. Until a game's replacement is proven offline, its parity ledger names the stacked effect and the trace that will prove the skip.
- **Two ways**: a fix in shared code or a pattern goes to every add-on that carries it.
- **Process**: one implementer at a time on one tree, on a verified plan; read-only surveys may run beside it. One writer per file at a time (2026-11-22): before a wave, list each task's files, and tasks that overlap run in sequence; two implementers may share a file only when their functions don't overlap and both briefs carry the same owner map (functions, slots, build-script parts; anything outside it is asked first; the branch that merges second rebases and reruns its gates, 2026-11-25). Parallel rounds each get their own worktree and game folder: check its base, give each agent its own scratch-file prefix (they share one scratchpad), merge one branch at a time, then verify the merged tree once (every target, the test suites, the harness, page dumps) before stamping. The batch checklist lives in `HANDOFF.md`, ticked in the commit of every step, so a stop or a compaction loses nothing. **Designs before code** for a new feature: the math with its paper or textbook source, where it runs (helper, add-on, which pass), bridge changes append-only, rows and defaults, the test plan with its controls, failure cases, rollback; one independent review of the design before the first commit (the reference suite's review found three blocking points). A bug round writes each cause and its plan before any code change and appends the results. **Review on top** (2026-11-24 / 25 rounds): each implementer works in its own worktree and branch (no push, no merge) and hands back; one read-only reviewer (Opus xHigh) reads the branch; the same implementer fixes the findings and the same reviewer re-checks until MERGE; the coordinator merges one branch at a time and builds the touched targets in the main tree (exit code and warning count against the target's baseline); nits found after a merge get their own small branch. A worktree without `bin` checks its compile before the review with `clang-cl /Zs` and the main tree's `compile_commands.json` commands: a raw line break in a tooltip literal once broke every add-on that includes `rt_scene.hpp` [989689840].
- **HDR review rules** from the RenoDX maintainers' reviews (ShortFuse, Musa; written down by boostedwarr): [references/hdr-review-rules.md](references/hdr-review-rules.md). Read it before any tone mapper, LUT, bloom, hue, gamma or PsychoV change, and before any page 1 row or preset (the maintainer's Page 1 and presets section there); one curve, once, on the untonemapped scene.
- **Every shipped shader first** (the maintainer, 2026-11-15: "You will never catch every shader that loads"): a game's shader work starts from an offline census of every shader it ships (all permutations in its packs or shader caches, read as plain data; nothing encrypted or protected), decompiled and sorted into families (tonemap, LUT, post, UI, lighting) with the permutations each setting selects. Traces only say which of them run where, in which order and on which formats. Nsight can't stand in for the game run in a ReShade game: GPU Trace takes no D3D11 or D3D9, and its Frame Debugger won't intercept ReShade's `dxgi.dll` (and its capture tool closed Steam once); the add-on's own frame trace or DevKit snapshot gives the whole frame instead.
- **Mods that ship shaders**: a game mod that ships its own shader files changes the hashes our replacements key on. Extract the mod's shaders and compare them with the game's: a shader whose logic is the same gets a twin row in that game's own twin table (the mod's hash on our replacement), never a utils-wide alias (it would also put full replacements over shaders whose logic changed). A changed shader also gets a twin row where our code only patches or names its draw; replacing it outright needs a port built on the mod's version, with the mod authors' OK and a credit unless they waive it. Check again at each release of the mod; a mod's installer can bring its own packs.
- **Nothing dropped**: every "not done", "later", "listed", "needs" or "found" line of an agent's report, and every line of an analysis report's ranked list (profiles, Nsight, censuses), becomes its own `HANDOFF.md` checkbox with an owner (an agent, the maintainer's decision, or a named trace) in the commit that merges or records the report. "Later" and "listed" are not states; "too big" needs a measured number. Read every report to its end before relaying it.
- **Ticks need evidence**: tick a box only when every part it names is done, the commit, test or run named in the tick. "Superseded by X" only when X names every part; a revert re-opens or annotates every box it undid (three ticks still cited a reverted sort); a partial `[~]` or mid-line box counts as open in every sweep; every step of a plan has a box, or it vanishes; "the maintainer decides" goes on his question list, not into a note; an agent's own "low value, not done" is no drop until the maintainer or the coordinator drops it. A tick audit (2026-11-22, every ticked box and plan step) found ticked boxes in every part of `HANDOFF.md` with parts nobody owned, and 10 of 166 plan steps with no box.
- **SHARED STEP**: a piece several games need is named SHARED STEP in the report and gets one owner for all games. Before starting other agents, write it into every game's parity ledger as SHARED STEP with that owner, or they build it twice (2026-11-14: one skip built by two agents).
- **Stale reports**: a brief that starts from a report carries every line it owns and names who owns the rest, each line checked first against `git log` and `HANDOFF.md`: a report can predate its own fix (2026-11-14: three fixes done the night before went into a brief again).
- **Parity ledger**: where a reference add-on of the same engine exists (Attila for Total War), the new game's ledger lists the reference's whole package, every row and feature HAVE, DONE, NEEDS A TRACE (scene named) or WON'T GET (proof). Per-game plans stop at their own end; only the ledger check sees the whole package. A new game gets the whole package in its first round. A WON'T GET gets an adversarial second look before it is written: name the exact blocker with its number, then try the route that replaces the blocking input instead of the pass. Two of Ryse's fell to it: the shadow-map skip (the readers rule under Measurement) and path-traced ambient (the ambient route under The helper and bridge); R.U.S.E.'s missing G-buffer blocked neither its RT GI nor its reflections (the same route; guides from its own shaders, [references/engines.md](references/engines.md)). Games of other engines keep a ledger against Attila's page too: R.U.S.E.'s and the Divinity games' in `tools/tw/parity/<game>.tsv`, Ryse's, Tales' and Expeditions' beside their plans (`tools/nontw/<game>/<game>.tsv`, one copy, written by that game's round [6701d711a]); `tw-port-checklist`'s `parity_check.py --games d1 d2 ru ry ta exr` checks them.
- **Git**: one commit per item with cause and numbers, pushed to the fork's `atn-mods` right away, never upstream. No tags (the maintainer tags). No Nexus text until the maintainer asks.
- **Builds**: never mix add-ons built before and after an upstream merge in one game folder. Release builds are stamped by the maintainer's private step; never rebuild after stamping.
- **Licences**: licence text for anything shipped; no code from mods without a licence (Arise-SDK is GPL-3.0: findings only, never its code). NVIDIA SDK code (NRD, SHaRC, RTXDI, RTXPT, OMM, Streamline) keeps NVIDIA's notice and is fetched at build time (`build/downloads`) or used as unmodified headers, never committed under the repo's MIT header; a sample without a licence (NRD-Sample) is read only; BSD-3 (Falcor) and Apache-2.0 (pbrt-v4) code may be used in tools with its notice. A reference written to check an estimator stays our own code.

## Measurement over manual testing

The maintainer's in-game hours are the cost to avoid. Every check that can run offline runs before a build reaches them.

- **One fixed scene per game** for costs and frame times: a replay, benchmark or save with a scripted camera move, the same every run (Attila: `tools/tw/bench/constantinople_bench.ps1`). Run it once after all of a batch's optimization rounds, each round's candidates as variants, with a named baseline build.
- **A quiet lock** while it measures: while `tools/tw/quiet_run.lock` exists nothing else starts (no build, no test exe, no WARP, no long script). Test exes once ran inside a measurement window and spoiled two starts; an agent's one-core Python check ran through all 8 starts of a bench: hold every agent's CPU work during a measured run, not only builds.
- **GPU work in three kinds** (the maintainer, 2026-11-22): correctness checks (dumps, NaN scans, register counts) run whenever their rule exists; timing and Nsight cost runs only through the maintainer's existing rules, on a quiet machine, in a natural gap between agents' work (a paused agent's prompt cache expires, and its resume re-reads its whole context); game runs last, with the maintainer's go.
- **No GPU number without a gate id**: a GPU timing claim about the TW helper (its passes on a recording) comes from the lab's gate (`tw-port-checklist`'s testing.md): A, A' and B interleaved, the A/A difference inside its threshold, the picture checked in the same job, reported as `[G-<date>-<n>]`, or marked `(old, no gate)`. "Within noise" needs the noise number. Nsight explains a time, it doesn't decide one. The game's own passes and add-ons without the helper keep their pass timer (Tools by question): such a line carries the marker `(pass timer, A/A ±N %)`, as a model line carries `(model, no gate)`.
- **A rule changed after seeing the results** is a fix to be judged, not a moved goalpost: say so, say why, and have the reviewer check that it hides no player risk before the re-run counts.
- **Crashes in the end batch** (the measured batch after a round's optimizations): its budget is one crash per kind (a leak: go on once with that start cut shorter; a pinned part: go on once with it off); a second of a kind, or any other crash, ends the batch. Every crash is root-caused (crash log, dump, pin) and fixed before the final bench.
- **Look verdicts are scored**: screenshots off and on against a reference, in one run (pause freezes the picture; settings changed while paused show no change). The quality scorer's scene has no fog, reflections or water (smoke only through its `smoke` feature, 300 particles in the sun's way): fog, reflection and water changes need their own WARP or harness check, no score.
- **Tools by question**: GPU passes by the add-on's own pass timer and frame trace; the CPU by PresentMon and a sampled WPR profile (`wpr` only through the maintainer's elevated tasks `RenoDX_WPR_Start` / `RenoDX_WPR_Stop`, never elevate another way); Nsight Graphics where the game is 64-bit and its protection allows attaching (it doesn't attach to 32-bit D3D11). Never work around a game's protection to attach a tool or read code. An A/B measures a change only where its code is on the critical path: find the waiting thread first.
- **Read the number the change moves**: in a CPU-bound view a GPU saving leaves the fps alone (GPU busy, the pass timer and the helper's profile show it: a torch shadow pick saved 1.7 ms of GPU, fps unchanged). A CPU saving that only turns into CPU wait (CPU busy -1.8 ms, frame time unchanged) means another thread or wait limits the frame.
- **The harness predicts the direction, not the frame**: a render-list sort, an instance gather and a 128-byte memcpy path won in the harness and lost or did nothing in game; D3D11 per-draw side work cost more in game than in the harness (batched unit capture: GPU busy -1.7 to -2.2 ms in game against 0.7 ms predicted; a reuse record -0.22 against -0.37). Only the bench decides a default.
- **Profile a statically found site before porting it**: render-list pushes found by reading the x64 code got 0 samples in Pharaoh and Shogun 2 battles (WPR, 2026-11-15).
- **Read a profile to its end before ranking**: on the thread that limits the frame, split every module's time by caller, system modules too (wow64cpu, ntdll, d3d11, the driver, the kernel), resolve samples that fall in no module (trampolines, allocated code), read inclusive subtrees so a long tail of small functions shows, and follow who readies the waiting thread. A list ranked from the top exclusive functions alone missed all four in Attila (2026-11-17): ~10 ms of night1's 39 ms render thread in system modules, 1.4 to 3.7 ms in no module, 22.7 ms in the game of which the listed functions held ~10, and stress's 16.5 ms a frame waiting on workers. A GPU trace the same way: per pass its L2 traffic, local-memory spills, instruction misses and occupancy limiter, and a kernel's cost split by removing its parts; another modder's path tracer showed its cost was traffic and spills, not math, and that its reordering (SER) was what kept instruction misses from tripling.
- **Measure before splitting a GPU kernel**: build variants that drop parts (trace only, no validation, no lights) and read time, registers and occupancy in Nsight. If a variant with more occupancy isn't faster, the kernel isn't occupancy bound and a trace / shade split (plus its hit record, ~32 B a texel each way) can't pay: Attila's paths 0.366 ms at 29% occupancy, trace only 0.288 ms at 37% and 0.287 ms at 50%: no split.
- **An estimator against its textbook form, not only against itself**: Torch Light in Path-Traced GI's light-picking next-event estimator against every light with its own shadow ray (pbrt's UniformSampleAllLights, exact for point lights) gave x1.0001 [1b0ea68f]; the estimator's own noise between two frames (0.980 to 1.020) sets the tolerance. Compare by formulation; copy nothing without a licence.
- **Every cited source gets a fidelity table** (the maintainer, 2026-11-25: "how can we be sure we didn't accidentally ignore a paper like this?"): a design that builds on a paper, an SDK or a guide lists each claim it uses (source + section), where it lives in our code, how a build proves it is compiled in (a DXIL count or a define check: the ray count showed RTXDI's temporal bias correction compiled out, step 4c M1), the test that fails if it breaks, and each deviation marked chosen (reason, the maintainer's word) or a bug. "Inspired by X" is not X: a method that reads another output from X's estimator (U2's torch ratio from one sum-target reservoir, 20 % error) is our own method with its own proof, and so is code written where the SDK has no function (RTXDI 3.2 has no DI spatiotemporal pass); it gets its own review. In the code (Forge, 2026-11-25: "every piece of code or blocks of code" cites, "every change ... marked with an explicit deviation and why it deviates"): each estimator block carries a source comment (paper section / equation, SDK file:line, spec section), or "ours" with the reason, and each departure from its source a deviation comment saying what differs and why. A reviewer opens the cited source and checks the block against it; a cite only being present proves nothing.
- **Fix it at the source, don't guard and cope** (Forge, 2026-11-25: "X game does this so I am going to guard and cope around it, even when that thing should be reworked from the ground up"): a guard, clamp, skip or special case is a deviation. Its commit names the root cause and why it is guarded rather than fixed. A guard around our own bug, or one whose cause is unknown, is a bug to rework, not a fix: give it a HANDOFF box to find and fix the cause. Safety guards stay (the maintainer, 2026-11-26: "leave the guards so we don't get any ... crashes / freezes"). A guard against a crash, hang, NaN or Inf stays in the code as a safety net after its cause is fixed. It must never be the fix, and a one-frame trace must show when it fires; hang caps (SHaRC depth, PTLAS) come off only once the cause is proven fixed. Before keeping a fix to someone else's code (Bend SSS, FidelityFX SSSR, RTXDI), show that the original is really wrong, and not that our inputs differ from what it expects.
- **A brute-force reference judges only after its own gates** (the TW helper's reference build, `tw-port-checklist`'s testing.md): closed forms (open sky, specular occlusion on an open plane), a furnace (its first run caught the reference's own bug: 0.761 where 1 was due [5d033f13]), its samplers on WARP against their moments and against pbrt-v4's and Falcor's on the same uniform inputs, per-texel group variances; and zero cost when off (shader headers byte-identical, every PE section identical once line numbers are aligned, the harness dump 0 differences over every mode, the same Nsight passes). Statistics: 4 or more replicates differing only in the start frame, 16-frame batch means, 8 or more seed groups for the reference, 30 or more independent units a mask (tiles at least twice the largest reuse reach), luminance and colour ratios, inputs frozen at the window's end, a NaN / Inf / negative census that fails the run. Synthetic controls must fail: the candidate x1.03 and a 1-texel shift read BIAS, a frozen candidate NOISY (replicates disagree beyond their variances). A named model variant splits a model delta from an estimator bias: ContactShade made ~95% of the raw paths' -12% in concave corners [3d755799]. A BIAS reproduced twice becomes a HANDOFF box; it closes only with its table PASS and its control still failing.
- **CPU trims keep the same decisions and bytes**: exact by construction (the same reads in the same order, values cached only while what they depend on can't change), proven by a cross-check switch that compares every reused value with a fresh call (TW: `RENODX_TW_STATE_CHECK`) and its control; a deterministic replay that drifts between variants means the change isn't exact (stop, revert). Engine code: bit-exact against the game's routine over every input.
- **A reader binds the resource and declares the slot**: compare each draw's bound slots with its shaders' declared ones (reflection, `dcl_*` lines); bound alone is no reader. Ryse's shadow maps were "bound for most forward draws", so their skip was called WON'T GET: 37 to 55 shaders a frame had them bound and never declared them, the real readers were 5 mask passes, hair and fog.
- **Scripted switches without the environment**: a game whose DRM wrapper relaunches it through Steam (Tales of Arise's SteamStub) never sees the launching shell's `RENODX_TW_*` variables. Write the same `NAME=value` lines into `renodx_test_hooks.txt` next to the exe (`twattila/test_hooks.hpp`: read at load, deleted at the first present), and delete it in the run's `finally` too. Don't restart Steam with the variables: every game started from Steam afterwards would inherit them.
- **A crash only with the mod**: repeat the player's exact action in three starts: vanilla (ReShade's proxy dll and the add-on renamed aside), ReShade only (the add-on aside), the full mod; fresh backups, hashes checked after the restore. It tells game, ReShade and ours apart in about ten minutes (Divinity 1's window switch: both controls survived, the mod crashed; the cause, our flip upgrade, is a row in `tw-port-checklist`'s `helper-fg-stability.md`). ReShade's "Reference count ... inconsistent" warning at a swap chain's release comes without any add-on too: no clue.
- **What the maintainer still tests**: look verdicts and what only a long session shows.
- **A run counts** only with a "ready" or "applied" line in a new log: a build that failed PSO creation once "passed", an old log was once copied.
- **A pass gate keyed to one trace's resources** is proven only for the settings that trace ran with. R.U.S.E.'s trace point waited for a main pass with its own depth (the MSAA trace's); with the game's MSAA off the main pass shares the pre-pass depth, so the rays, GT-VBAO, Bend and GT-VBGI never ran in game (2026-11-16). Take one trace per AA mode, or any setting that changes the passes, before trusting a gate, and keep a test case per mode.
- **No status line at all is a finding**: no "tracing" and no "no trace this frame (...)" line means the add-on never asked; look at its trace point, not at the helper. Every request path logs its first answer and why not.
- **A replacement proven offline still needs its in-game coverage check before it is a default**: the dark-pixel share of the ground and of each caster kind (trees, units, buildings) with ours against the game's. R.U.S.E.'s rays passed the combine proof on all 1,185 shaders and still lost every tree and unit shadow in game (casters missing from the ray scene).
- **A cost with no visible change** (R.U.S.E.: GT-VBAO +2.5 ms, Bend +1.1 ms, nothing in the shots) is checked with the method's debug view before any default: wrong inputs often still cost time.
- **Screenshots during loads**: ReShade's screenshot key doesn't capture videos (Tales' opening movie looked like a stuck title). While loading, use a capture of the game window to see where the menus are; ReShade shots for looks.

## The maintainer's test list

- 10 lines or fewer, the most important first, grouped by scene so one start covers each scene.
- Each line: scene; exact row name and value; what to look for; which file to send. First line a control: rows off looks like the last version.
- Every Experimental row gets one A/B line naming the decision it drives. A row's cost shows only with its content on screen: name the scene and camera.
- Prefer what the build reports itself ("applied" lines, profiles, frame traces, pixel traces): then the maintainer only sends the logs and the ini.
- Dry-run each line, and every agent run's plan, against a page dump of the maintainer's current preset: the row shows, the key exists in this game, every log line the plan relies on exists in the build.
- Never ask what an offline check or an allowed agent run can show; never repeat an unchanged item. A longer scripted list belongs to agent runs only.

## Agents and tools

- **Standalone test exes** are allowed, built only in `tools/tw/testbin`, which the maintainer excluded in Bitdefender (nothing downloaded goes there). Agents' scratch scripts and their outputs go there too, under `tools/tw/testbin/scratch/<prefix>/`, big output into a file there, not a task's output (Bitdefender quarantined five scratch files elsewhere in 35 minutes, 2026-11-22). A file Bitdefender quarantined and the maintainer restored may be copied there under its own name. Never rename, alter or pack a file to get past a scan, never touch Bitdefender's settings; a file still blocked: stop that path and tell the maintainer.
- **Load limits**: every build goes through the build gate the round names (`tools/tw/round_notes/gated_build.ps1`: 4 build slots shared with `take_slot.sh` (`tools/tw/testbin/scratch/build_slots/slot1..4.lock`, v1 lock records, so a dead build's slot is taken over at once), a slot taken only with at least 12 GB of memory available for a TW or Unreal add-on (one translation unit peaks at 9-11 GB; 4 GB for the rest), `-j 4`, the plain CMake target names; a trial of 6 slots ran out of memory, 2026-11-24). While a GPU lab session or a bench may run, builds and suites run at below-normal priority, and a coordinator's "build window closed" stops new builds: write the code and tests, build later. Start scripts with `powershell -ExecutionPolicy Bypass -File` (plain `-File` is refused by the execution policy). End a hung build at once (`setup-game-mod-dev`'s build steps): it blocks every build queued behind it. Read a build's last lines before writing "exit 0" into a commit or report (the same steps: a commit once claimed a build that never ran). One GPU job at a time through `tools/tw/gpu_job.lock`: new scripts take it through `tools/tw/lab/gpu_lock.py` / `GpuLock.psm1` (a v1 record: pid, process start time, script), and only a v1 record whose process is gone or reused is taken over. Older scripts' lines (`test/tw_rt_open_sky`'s `-Lock` among them) are only reported, never taken over; nobody clears the lock by hand, and a dead one goes to the coordinator.
- **Worktrees** may link `build\downloads` and `external\*` into the main checkout as junctions (read-only inputs), never `bin`: a worktree's builds would overwrite the main checkout's add-ons; give tools that need its decompiler or DXC the main checkout's `bin` as an argument. Delete the links alone before any recursive delete of a worktree. A coordinator never `cd`s into an agent's worktree (PowerShell keeps the location, and the session's working folder moves with it): absolute paths and `git -C <worktree>`.
- **Deletes**: no recursive delete without the maintainer's yes, an agent's own fresh outputs included: leave them in place (2026-11-21). Never delete reference runs, Nsight traces or recordings; clean-ups are old analysed WPR files, testbin DLL copies and closed batches' shots, listed with sizes first and deleted only on the maintainer's yes (the lab's own dump clean-up is his rule).
- **Hand-backs first**: an agent's final report is saved to a file and logged in `HANDOFF.md` (committed) before anyone acts on it; what lives only in a conversation is lost at the next compaction.
- **Safety stops** are Anthropic's check on the model's output, not the maintainer's permissions: no setting switches them off. Report the exact action; retry once, unchanged, only on the maintainer's go. His standing fallback: a safety-stopped Opus design, or a stopped Opus review of engine code, gets one Sonnet xHigh run as that one retry. A second stop, or one that says "not again, even reworded", ends that path. A permission or antivirus refusal is the same: stop that path, report, no workaround. Never claim an agreement the maintainer didn't make.
- **Fix tooling now**: a tool that is broken, crashes, is far too slow or can't answer its question is fixed right away, not deferred or guessed around. Every run script states its expected time and a deadline and logs each phase; every measured gain carries its A/A noise number. A safety stop or a permission block is not a broken tool; a new switch in a script the maintainer runs by rule needs his new rule.
- **Time budgets** (Forge, 2026-11-25; safe-point stop: ATN, same night): every agent brief states an expected time, citing a past agent of the same kind in `tools/tw/round_notes/agent_times.tsv`, and a deadline of twice that. Time spent waiting for the GPU lock or for the coordinator's resume does not count; the hand-back reports it apart. At the deadline the agent stops at a safe point, never mid-command: it finishes the running command, releases the GPU lock and any other lock it holds, commits or writes a resume note, and hands back with the cause of the overrun (what was slow, why) and a new estimate. The coordinator resumes it (SendMessage keeps its context) only with a written reason in the time log. Every overrun gets a cause and a fix: a wrong estimate gets a new number for the next brief, a slow or broken tool gets fixed now plus a pitfall row, a lock wait goes to the GPU lock queue fix. Every hand-back ends with its time per step. No command runs untimed: a single command gets a hard timeout (its price history, or the watchdog's default), which stops the command, not the agent. A run far over its usual time is a fault to find, not the tool's normal cost.
- **Gates and pitfalls** (`tools/tw/gates`, `tools/tw/pitfalls`): the maintainer's gate hook checks agents' commands and edits (in shadow mode it only logs). Its block rows: no `--platform` to ngfx, no deletes or moves of traces, reference runs or recordings, no deletes by `*.addon32.*`, no hand-cleared GPU lock, no direct player starts. `tools/tw/gates`, `tools/specs` and `pitfall_check.py` are protected: an agent proposes a new block row in its report, and the maintainer adds it or opens a `files` override for it (his `gate_override.ps1`, never run by an agent). The gates' tool owner swaps `gate_hook.py` and its tests only after their reviews and a green mirror suite; in enforce mode that swap too needs the maintainer's `files` override. A mistake that cost a run, a review finding or a correction by the maintainer gets a row in `tools/tw/pitfalls/<kind>.tsv` (or its hit count + 1) in the fix's change, named in its commit message (`tools` is no git repository), with its prose in the skill or memory file it names; a row with two hits gets a script check. A crash is closed only with four parts: the producer → consumer chain that broke, the exact mistake (the wrong assumption, the change and its commit), a pitfall row, and the check that stops it coming back (a test, a script check or a proposed block row). API names on changed lines of TW D3D or HLSL code are looked up first in the local specs (`tools/specs/spec.py`), and the lookups' `spec:` cites go into the commit message.
- **Long rounds**: an implementer keeps a status section in its plan (what is done, with hashes; what is next), updated at every commit; when its context runs out, a successor continues from that section in the same worktree (R.U.S.E.'s round went through six implementers without losing work). A build gate that waits (memory, slots) stops no agent: queue the build in the background; under "build window closed" queue nothing.
- **Patch scripts** are written to a file with the Write tool, not a shell heredoc (backslashes collapse: a `\n` in a C++ tooltip string became a real line break, twice, the second time breaking every add-on that includes `rt_scene.hpp` [989689840]; raw NUL bytes end up in sources). Text searches skip a file with a NUL as binary: find such files with `rg -a`, then fix them.
- **Reviews, bug hunts and planning** run on the normal model: one independent review of a round's merged tree, then one agent for its fixes. Designs and plans are Opus at xHigh, never Sonnet unless the maintainer says so; engine-code implementers run on the model the round's plan names at high effort, reviewed by Opus at xHigh, and the same implementer fixes the findings. Fable only when the maintainer asks for it, or after asking them, for a problem that can't be solved otherwise or a really big change: it costs far more. Re-check every finding of a review or audit against the code before fixing it, and size the fix by reading around it: of eight HDR audit findings one was false (a `#define` already pointed at an SDR-safe injection) and two fixes were bigger (WH2's FXAA had a second clip; Thrones and WH1 had compute DOF blurs the audit missed).
- **Effort by job** (the maintainer, 2026-11-17): runs and benches at low effort, one runner for a whole batch; a plain bench one medium agent that runs and judges; a high judge only where a batch's results need deep analysis; analysis, plans, designs and reviews of optimizations (profiles, traces, the list of everything to improve) at xHigh; implementers at high; one xHigh review of the merged result before its bench. An agent's tokens go mostly to its fixed reading (plans, logs), not to its effort: a medium agent that ran and judged ~41 starts cost 327k tokens, a low runner of 3 starts 84k plus a high judge 241k. The medium all-in-one agent's candidate list was the one that missed the profile's tail (Measurement).
- **Data-collecting agent runs** (start, traces, logs, quit), where the maintainer allows them, run at low effort: they collect; the reading stays offline. Where the maintainer loads a save, the run hands over by files: the agent writes `NEED_SAVE.txt` (what to load), waits for `SAVE_LOADED.txt` and `FOCUS_OK.txt` (every always-on-top window off: one, or an unfocused game, makes PresentMon's numbers invalid; Divinity 2 gave 247 fps valid against an invalid 30), and quits the game at the end as its done signal.

## The helper and bridge

The TW helper (`renodx-tw-dlaa64.exe`, `src/games/twattila/dlaa_helper/`) also serves non-TW add-ons (Ryse, Expeditions: Rome, Shogun 2) through `twattila/dlaa_bridge.h`. Its internals are in `tw-port-checklist`'s `helper-fg-stability.md`.

- **Newest only**: every add-on on the bridge builds against today's `dlaa_bridge.h` and ships with the helper built from the same commit, never an older copy. An add-on built against an older bridge is rebuilt and shipped with the matching helper.
- **Locks and ReShade's events**: ReShade fires `destroy_pipeline` / `destroy_resource` from inside later D3D11 calls (a draw, a flush, a Release), on the calling thread. A lock held across any D3D11 call is never taken by a destroy callback; give the callback's map its own small lock (`rt_core`'s `pixel_coverage_mutex`, Expeditions' first rays crashed on this). Rays on at launch belong in every first data run of a `scene_draw` host.
- **Path-traced ambient enters where the engine's does**: find the one input that carries the game's diffuse ambient (a probe cube array, an ambient constant, the SSAO apply), replace that input (a black 1x1 cube, the constant times a mask) and add the paths' light at that place, instead of replacing the lighting pass. Ryse's tiled lighting CS took its diffuse ambient only from the probe cube array at t34; R.U.S.E.'s comes from `uniAmbientColor`. It needs no G-buffer: `rt_core`'s light bounce reads positions and last frame's light, and the game's own patched shader multiplies it by its albedo; only ray-traced reflections need guides (D3D9: [references/engines.md](references/engines.md)). Path-Traced Ambient stands in for the game's ambient and its AO together (the paths bring the sky's light, their blocked rays are the occlusion). Ray-traced AO also replaces the game's own AO (its SSAO / SSDO / HBAO goes off under the row, never multiplied on top) and occludes the game's ambient, without path tracing (the maintainer, 2026-11-16). The switch to path-traced ambient holds over frames the helper missed (a grace window, one constant for every host, `tw-port-checklist`'s ao-gi.md): one missed frame once gave 2.5 s of the game's ambient [90fd58a5].
- **Texture LOD bias with every render scale below 100 %**: every game that renders below the output size (the helper's upscalers, the game's own scale) gets the bias log2(scale) on the scene's wrapping samplers, the anisotropic ones and the trilinear ones terrain and buildings sample through, never clamping or post samplers, main view only; the bias adds to the game's own. Take the scale from the size the game really renders at, not a mode index (a game with its own float scale had the row greyed out). Proof: log the samplers by kind and bias at a low scale. Total War details: `tw-port-checklist`'s render-scale-dlss.md.
- **Ray Reconstruction in a D3D11 game goes through NGX D3D12** (`twattila/dlaa_helper/rr_d3d12.hpp` in the helper; Tales' in-process copy was deleted once its helper route came [ae86e8603]): NVIDIA's D3D11 RR followed by a GPU wait (or a shared-fence wait) gave black output or an access violation in nvwgf2umx. D3D11 Super Resolution is fine.

## Device removal and resource clones

- **A removed D3D12 device passes the usual checks**: its fences read all ones (every wait returns at once) and allocator and list resets succeed, so an own D3D12 path goes on "running" on stale results. Every such path also fails on `GetDeviceRemovedReason` and on a failed queue `Signal`, stops for the session with one status line carrying the HRESULT ("Failed: the D3D12 queue stopped (0x887A0005)."), returns early from every later capture while failed, and its Retry releases a removed device so the next try makes a new one (Tales' in-process rays [43a2acaf2, fc8b08a3b]). Test it with a forced removal (`RENODX_TW_TEST_REMOVAL`, the device removed at the third trace) and a control on the old code that must fail. The TW helper's own rules (a new shared fence, own devices) are in `tw-port-checklist`'s helper-fg-stability.md.
- **The swap chain proxy** (`device_proxy`): after a failed ResizeBuffers, Present TEST or Present, `GetDeviceRemovedReason` decides; a removed proxy device logs one error line and keeps the proxy off for the process: the host presents natively, a restart brings HDR back [8bdbfa0a8]. Its detach goes by the attach's own flag, not by a request the removal turned off [9e1718410]. `test/tw_device_proxy_removal` (WARP, one process per removal site).
- **utils resource clones**: utils redirects a bound view only when that view's clone flag is on, and an engine that makes a render target's views with the texture (UE4) keeps reading the original after a copy that set only the resource's record. Turn a copy's destination on through `GetResourceClone(dest, {.require_enabled = false, .allow_create = false, .activate = true})` (`utils/resource_upgrade.hpp`'s `ResourceCloneOptions`), which sets every view (Tales' frame copy [ad85b2142]), but never a swap chain buffer's clone from a copy: the swap chain module owns those (in scRGB the back buffer's clone is its pass's scratch: turned on, a capture copied into it and the pass overwrote it, black [185ab5554]). Copies and resolves go only through an enabled clone; a disabled side uses the resource itself (swapchain_v2's scRGB mode keeps a disabled scratch clone of the back buffer: a copy into it gave a black frame [6eacd8a84]).

## The fast draw dispatch

`utils/command_action_fast.hpp` keeps, per D3D11 command list, which `command_action` callbacks each bound pipeline brings, instead of looking them up on every draw. `command_action`'s registry is one per process, shared by every add-on, so the fast path is on only while **every** module attached to `command_action` opted in: one module without it (the DevKit, an older partner add-on) turns it off for all, and the log says so.

- Any add-on that uses `command_action` (through `mods::shader` or `command_action::Use`) calls `command_action::fast::Use(DLL_PROCESS_ATTACH)` right after that attach, and `fast::Use(DLL_PROCESS_DETACH)` just before its detach. TW add-ons with resource upgrades call `twattila::draw_dispatch::Use` instead (it adds the resource upgrades' gate). Since 2026-11-15 every TW add-on and Ryse, Tales and Expeditions (one add-on each) opt in; a DevKit next to the game still turns it off.
- A new command-wide callback (`command_action::Register` without a shader hash) gets a `command_action::fast::SetGate` that repeats its own first early return (cleared before its `Unregister`), or a comment saying why it runs on every draw; a gate whose per-pipeline answer changes after the pipeline's init calls `fast::Invalidate()`.
- Check: `test/tw_draw_dispatch` (x86 and amd64) and the replay oracle in `tools/tw/draw_redesign` (fast against `--legacy`) show 0 differences.
